# 1 交付範圍與製作順序

本計劃將遊戲規格轉為可逐階段檢查的製作工作。此次交付僅為文件；進入遊戲開發仍需使用者確認開工。開發以可玩的前五天為首個里程碑，再擴充人口、探索、季節與狩獵。

## 完成定義

第一版必須能從五隻泡泡在洞外的全新開局，經過採集與建造，完成五日教學並持續生活。每個系統都有可觀察狀態與等待原因；畫面切換、存檔與時間加速不能改變資源帳。美術素材必須在手機實際顯示大小下驗收。

| **階段**        | **主要產出**                             | **前置依賴**             |
|-----------------|------------------------------------------|--------------------------|
| M0 規格與資料   | 狀態清單、初始資料、配方表、五日收支表   | 確認規格與開工           |
| M1 畫面與操作   | 雙場景可拖曳原型、泡泡動畫樣本、遮擋測試 | M0                       |
| M2 模擬核心     | 時鐘、尋路、派工、搬運、需求與存檔       | M1 的空間與輸入規則      |
| M3 完整生活循環 | 挖掘、家具、採集、砍樹、農耕與庫存       | M2                       |
| M4 五日體驗     | 教學、平衡、正式首批美術與回饋           | M3                       |
| M5 手機驗收     | 實機問題修復、性能與發佈候選包           | M4                       |
| M6 後續擴充     | 人口成長、探索、狩獵與季節               | 第一版穩定且範圍另行確認 |

## 排程原則

以依賴與驗收通過決定進度，暫不承諾日期。工期取決於實機限制、美術動畫量與試玩修改次數；M1 完成後再估算。若超出成本，先縮減物品種類與裝飾，不削掉任務排程、基本需求或存檔正確性。

每階段交付可檢查版本、簡短變更說明、驗證結果與剩餘問題。使用者主要在美術樣本、五日試玩和後續擴充三個節點給方向回饋；例行修正可在已授權範圍內持續完成。

# 2 原型與模擬核心

## M0 整理可執行資料

建立地格、物品、居民、配方、作物、任務與教學條件的資料字典；每項分配穩定 ID。列出已確認與可調參數，將食物份數和搬運單位分開。先試算五日食物需求、休息與工作總量，確認初始地圖有足夠資源。

交付：初始地圖配置、最小配方表、物資收支表及驗收案例。通過條件：五日流程沒有必需品相互依賴的死結，暫定數字都有調整位置。

## M1 先驗證手機畫面

以少量正式品質素材搭出 15 格寬地下與地表局部等角場景；完成拖曳、縮放、選取、場景切換及樹冠淡化。先製作一套泡泡基本身體，測試五種色盤與可卸配件，試做待機、跳行、搬運及工作。

使用擁擠樹旁、兩個物品重疊、二十隻同屏等測試場景，檢查辨識與點選。素材檢查包含腳底錨點、像素尺度、家具佔格及兩場景角色比例。通過後才擴充素材，避免整批重畫。

## M2 建立獨立於畫面的模擬

建議使用 TypeScript 與 2D Canvas 或同類圖集渲染；正式框架於技術驗證後決定，不在文件中鎖定套件版本。模擬狀態與畫面分離，以固定遊戲步進處理時間，畫面另行插值。地表視角投影不改變物品與居民的世界座標。

先做跨場景入口節點與四向尋路，再做任務領取、資源預約、兩欄搬運與交付。隨後加入飢餓、休息、中斷與恢復。最後接存檔，序列化居民、地圖、物品、任務、需求帳、教學與隨機狀態，包含格式版本及舊檔處理。

通過條件：五隻可處理有限資源而不重複取得；取消、缺料、滿倉、封路與休息能恢復；存檔重載前後資源總量一致。背景切換與加速不得讓需求重複計算。先用簡單圖形驗證行為，再接動畫。

# 3 生活循環與美術整合

## M3 完成可以持續運作的家園

依順序接入標記挖掘、區域指定、基本建造、地表採集、小樹砍伐與農地。每項都經過同一任務與庫存流程，不為教學另寫會跳過施工的捷徑。補上材料不足、等待人手、無路可走、倉庫已滿等回饋。

配方先限於草窩與箱子；飲食區可先席地用餐。採集先限三類食物，作物先一種；工作台、斧頭與大型樹木依流程需要再加入。水邊取水與工具取得必須形成可完成鏈條，不能讓澆水依賴尚未解鎖的工具。

通過條件：無教學介入也能完成採集到入庫、吃飯到恢復、領料到建成，以及播種到再播種；未顯示場景也持續工作。

## M4 加入前五日引導與首批素材

教學以條件判定，不綁死日期。補上已完成追認、提示收起、一步多種解法與居民簡短回應。建立標準開局與至少兩種失誤路線：延後採集，以及先蓋太多東西；驗證玩家仍能補救。第五日以兩日食物儲備為目標。

| **素材組** | **首批範圍**                                                                   |
|------------|--------------------------------------------------------------------------------|
| 居民       | 共用身體與五色盤；至多一個配件；待機、跳行、搬運、挖掘、砍伐、澆水、吃飯、睡眠 |
| 地下       | 土、地板、牆緣、頂端出口；箱子、草窩、基本用餐配置                             |
| 地表       | 草地、道路、水、樹、岩石、山洞入口、少量發光元素                               |
| 互動物     | 莓果、蘑菇、堅果、木材、纖維；種子與作物生長階段                               |
| 介面       | 選取框、任務狀態、區域標示、資源列、時間控制與教學提示                         |

資產需記錄原生尺寸、錨點、方向、佔格、動畫幀與遮擋範圍。環境不補滿碎花，採集物必須在手機縮圖仍辨識。音效可先做選取、交付與完成提示；完整配樂另列範圍。通過條件：全新存檔完成五日循環，沒有為演示而直接補資源的流程。

# 4 驗證與後續擴充

## M5 手機驗收與交付

先以使用者實際手機及一台較低效能裝置建立基準，至少檢查 iOS Safari 與 Android Chrome。測試直向、安全區、拖曳與縮放、背景恢復、低電量時表現、瀏覽器重載和本機存檔失敗。網頁不預設需要帳號或伺服器。

| **驗證項目** | **應取得的證據**                             |
|--------------|----------------------------------------------|
| 時鐘         | 1 倍和 2 倍完成相同遊戲時間，食物消耗一致    |
| 任務         | 多居民同搶資源、取消與重新領取後總量守恆     |
| 路徑         | 挖開通道後等待工作恢復；家具不能封住唯一出口 |
| 存檔         | 搬運、施工與進食中重載，不複製或遺失資源     |
| 五日平衡     | 起始 15 份可銜接再生採集；達成兩日儲備       |
| 畫面與性能   | 五隻順暢；二十隻壓力場景記錄幀率與選取反應   |
| 觸控與遮擋   | 樹後角色和物品可選；拖曳不會誤下指令         |

單元測試聚焦需求帳、資源預約與任務狀態轉換；整合測試覆蓋跨場景搬運、施工和農耕；手動實機驗證像素畫面與觸控。保留可重播的固定種子五日案例，但也需測不同隨機開局，避免只對單一案例平衡。

## 主要風險與處理

樹木遮擋以疏密布局、局部淡化和候選選取處理。居民卡工先改善狀態與等待原因，再談增加工作種類。素材量過大時先減類別與裝飾，維持共用角色系統。若五日糧食不足，調整可見資源、產量或工時，保留每隻每日一份的核心規則。

## M6 分開定義後續內容

先定人口擴增條件，再驗證新增人口的食物與床位壓力；再擴地表與資源分布。狩獵可先以一種生物、一種食材與可撤退遭遇試做，確認出征人手、掉落搬運、受傷與食物收益。完整戰鬥、烹調與四季各自另寫規格後才進入製作。

第一版完成時交付可玩預覽、原始碼與資產、建置方式、存檔格式說明、測試結果及待辦清單。發佈目的地另依使用者指示；本計劃不代表已開始開發或公開發佈。
